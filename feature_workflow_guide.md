# Flutter Clean Architecture: Feature Workflow Guide

Adding a new feature (like **Login**) in a Clean Architecture setup requires a structured approach to ensure separation of concerns. The recommended workflow is **Inside-Out**: start with the core business logic (Domain), move to the data integration (Data), and finish with the UI (Presentation) and Dependency Injection.

Here is a step-by-step guideline using a **Login Feature** as an example.

---

## Step 1: Domain Layer (Business Logic)
The Domain layer contains the core rules of your application. It is independent of any other layer.

### 1.1 Create the Entity
Entities are plain Dart classes that represent your core data objects.
- **Path**: `lib/domain/entities/user_entity.dart`
```dart
import 'package:equatable/equatable.dart';

class UserEntity extends Equatable {
  final String id;
  final String token;

  const UserEntity({required this.id, required this.token});

  @override
  List<Object?> get props => [id, token];
}
```

### 1.2 Create the Repository Interface
Define the contract for data operations. The actual implementation will live in the Data layer.
- **Path**: `lib/domain/repositories/auth_repository.dart`
```dart
import '../entities/user_entity.dart';

abstract class AuthRepository {
  Future<UserEntity> login(String email, String password);
}
```

### 1.3 Create the Use Case
Use cases orchestrate the business logic. Each use case should generally have one single responsibility.
- **Path**: `lib/domain/usecases/login_usecase.dart`
```dart
import '../entities/user_entity.dart';
import '../repositories/auth_repository.dart';

class LoginUseCase {
  final AuthRepository repository;

  LoginUseCase(this.repository);

  Future<UserEntity> call(String email, String password) async {
    return await repository.login(email, password);
  }
}
```

## Step 2: Data Layer (External Integration)
The Data layer handles API calls, databases, and mapping JSON to Models.

### 2.1 Create the Model (using json_serializable)
Models extend Entities and add serialization (e.g., `fromJson`, `toJson`). By using `json_serializable`, we can automatically generate this boilerplate.
- **Path**: `lib/data/models/user_model.dart`
```dart
import 'package:json_annotation/json_annotation.dart';
import '../../domain/entities/user_entity.dart';

// This file will be generated by build_runner
part 'user_model.g.dart';

@JsonSerializable()
class UserModel extends UserEntity {
  const UserModel({required super.id, required super.token});

  factory UserModel.fromJson(Map<String, dynamic> json) => _$UserModelFromJson(json);
  Map<String, dynamic> toJson() => _$UserModelToJson(this);
}
```

### 2.2 Create the Remote Data Source
Data sources handle the actual network/database calls using `DioClient`.
- **Path**: `lib/data/data_sources/auth_remote_data_source.dart`
```dart
import '../../core/network/dio/dio_client.dart';
import '../models/user_model.dart';

abstract class AuthRemoteDataSource {
  Future<UserModel> login(String email, String password);
}

class AuthRemoteDataSourceImpl implements AuthRemoteDataSource {
  final DioClient dioClient;

  AuthRemoteDataSourceImpl({required this.dioClient});

  @override
  Future<UserModel> login(String email, String password) async {
    final response = await dioClient.post(
      '/auth/login',
      data: {'email': email, 'password': password},
    );
    return UserModel.fromJson(response.data);
  }
}
```

### 2.3 Implement the Repository
The repository implementation maps Data layer responses (Models) to Domain layer requirements (Entities).
- **Path**: `lib/data/repositories/auth_repository_impl.dart`
```dart
import '../../domain/entities/user_entity.dart';
import '../../domain/repositories/auth_repository.dart';
import '../data_sources/auth_remote_data_source.dart';

class AuthRepositoryImpl implements AuthRepository {
  final AuthRemoteDataSource remoteDataSource;

  AuthRepositoryImpl({required this.remoteDataSource});

  @override
  Future<UserEntity> login(String email, String password) async {
    // This model extends UserEntity, so it's a valid return type.
    return await remoteDataSource.login(email, password);
  }
}
```

## Step 3: Presentation Layer (UI & State)
This layer handles what the user sees and interacts with.

### 3.1 Create Reusable Widgets
If you need custom inputs or buttons, create them first.
- **Path**: `lib/presentation/widgets/custom_text_field.dart`
```dart
import 'package:flutter/material.dart';

class CustomTextField extends StatelessWidget {
  final TextEditingController controller;
  final String hintText;

  const CustomTextField({super.key, required this.controller, required this.hintText});

  @override
  Widget build(BuildContext context) {
    return TextField(
      controller: controller,
      decoration: InputDecoration(hintText: hintText, border: OutlineInputBorder()),
    );
  }
}
```

### 3.2 Create the Bloc (Events & States)
Use Bloc or Cubit to manage the UI state.
- **Path**: `lib/presentation/bloc/auth/auth_event.dart`
```dart
abstract class AuthEvent {}

class LoginSubmitted extends AuthEvent {
  final String email;
  final String password;
  LoginSubmitted(this.email, this.password);
}
```

- **Path**: `lib/presentation/bloc/auth/auth_state.dart`
```dart
abstract class AuthState {}

class AuthInitial extends AuthState {}
class AuthLoading extends AuthState {}
class AuthSuccess extends AuthState {}
class AuthFailure extends AuthState {
  final String error;
  AuthFailure(this.error);
}
```

- **Path**: `lib/presentation/bloc/auth/auth_bloc.dart`
```dart
import 'package:flutter_bloc/flutter_bloc.dart';
import '../../../domain/usecases/login_usecase.dart';
import 'auth_event.dart';
import 'auth_state.dart';

class AuthBloc extends Bloc<AuthEvent, AuthState> {
  final LoginUseCase loginUseCase;

  AuthBloc({required this.loginUseCase}) : super(AuthInitial()) {
    on<LoginSubmitted>((event, emit) async {
      emit(AuthLoading());
      try {
        await loginUseCase(event.email, event.password);
        emit(AuthSuccess());
      } catch (e) {
        emit(AuthFailure(e.toString()));
      }
    });
  }
}
```

### 3.3 Create the UI Page
The UI listens to state changes and dispatches events.
- **Path**: `lib/presentation/pages/login_page.dart`
```dart
import 'package:flutter/material.dart';
import 'package:flutter_bloc/flutter_bloc.dart';
import '../bloc/auth/auth_bloc.dart';
import '../bloc/auth/auth_event.dart';
import '../bloc/auth/auth_state.dart';
import '../widgets/custom_text_field.dart';

class LoginPage extends StatelessWidget {
  final TextEditingController emailCtrl = TextEditingController();
  final TextEditingController passCtrl = TextEditingController();

  LoginPage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Login')),
      body: BlocConsumer<AuthBloc, AuthState>(
        listener: (context, state) {
          if (state is AuthSuccess) {
            // Navigate to Home
          } else if (state is AuthFailure) {
            ScaffoldMessenger.of(context).showSnackBar(SnackBar(content: Text(state.error)));
          }
        },
        builder: (context, state) {
          if (state is AuthLoading) return const Center(child: CircularProgressIndicator());
          
          return Padding(
            padding: const EdgeInsets.all(16.0),
            child: Column(
              children: [
                CustomTextField(controller: emailCtrl, hintText: 'Email'),
                const SizedBox(height: 16),
                CustomTextField(controller: passCtrl, hintText: 'Password'),
                const SizedBox(height: 24),
                ElevatedButton(
                  onPressed: () {
                    context.read<AuthBloc>().add(
                      LoginSubmitted(emailCtrl.text, passCtrl.text),
                    );
                  },
                  child: const Text('Login'),
                )
              ],
            ),
          );
        },
      ),
    );
  }
}
```

## Step 4: Dependency Injection (GetIt)
Finally, tie everything together so GetIt can provide the necessary dependencies to your Bloc.

- **Path**: `lib/core/di/dependency_injection.dart`
```dart
import 'package:get_it/get_it.dart';
// ... other imports
import '../../data/data_sources/auth_remote_data_source.dart';
import '../../domain/repositories/auth_repository.dart';
import '../../data/repositories/auth_repository_impl.dart';
import '../../domain/usecases/login_usecase.dart';
import '../../presentation/bloc/auth/auth_bloc.dart';

final GetIt getIt = GetIt.instance;

Future<void> setupInjector() async {
  // 1. Core (Network)
  // ... existing DioClient setup

  // 2. Data Sources
  getIt.registerLazySingleton<AuthRemoteDataSource>(
    () => AuthRemoteDataSourceImpl(dioClient: getIt()),
  );

  // 3. Repositories
  getIt.registerLazySingleton<AuthRepository>(
    () => AuthRepositoryImpl(remoteDataSource: getIt()),
  );

  // 4. Use Cases
  getIt.registerLazySingleton<LoginUseCase>(
    () => LoginUseCase(getIt()),
  );

  // 5. Blocs
  getIt.registerFactory<AuthBloc>(
    () => AuthBloc(loginUseCase: getIt()),
  );
}
```

## Step 5: Code Generation Commands

Whenever you add new Models with `@JsonSerializable()` or configure new classes using an automated DI package like `injectable`, you **must** run `build_runner` to generate the corresponding `.g.dart` (for JSON models) and `.config.dart` (for GetIt DI) files.

### 5.1 Build Once
If you just want to run the code generator once and build all necessary files, execute the following command in your terminal:
```bash
flutter pub run build_runner build --delete-conflicting-outputs
```

### 5.2 Watch for Changes (Recommended for development)
If you are actively developing and constantly adding new models or dependencies, it's highly recommended to keep the generator running in the background. It will automatically update `.g.dart` files every time you hit save.
```bash
flutter pub run build_runner watch --delete-conflicting-outputs
```

## Summary Checklist for a New Feature
- [ ] `domain/entities/` -> Create Entity
- [ ] `domain/repositories/` -> Create Interface
- [ ] `domain/usecases/` -> Create Use Case
- [ ] `data/models/` -> Create Model using `@JsonSerializable()` (extends Entity)
- [ ] `data/data_sources/` -> Create Remote Data Source
- [ ] `data/repositories/` -> Implement Repository
- [ ] `presentation/widgets/` -> (Optional) Create Reusable UI Components
- [ ] `presentation/bloc/` -> Create Event, State, and Bloc
- [ ] `presentation/pages/` -> Create UI Page
- [ ] `core/di/` -> Register Data Source, Repository, Use Case, and Bloc in GetIt
- [ ] Run `flutter pub run build_runner build --delete-conflicting-outputs` to generate `.g.dart` model files and DI files.
